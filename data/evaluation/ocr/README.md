# OCR fixtures

`commerce_synthetic_policy_scan_demo.pdf` is an image-only, two-page synthetic fixture for OCR Lab and upload-path evaluation. Its visible warnings mark it as test-only; its prose and logistics table values are invented. It is not an official policy, must not be indexed into the Commerce knowledge base, and must not be used as business evidence.

`commerce_scan_ground_truth.json` contains a visual transcription of both rendered pages, including the three sample table rows. Run `uv run python scripts/processing/evaluate_ocr.py --engines tesseract --output artifacts/evaluation/ocr/commerce-scan-ocr-smoke.json` to compare the local OCR output against the fixture. This checks that the evaluator, page rendering, text OCR, and table-anchor scoring work end to end; it is not an OCR engine benchmark or a production quality claim.

`commerce_synthetic_degraded_scan_demo.pdf` is a deterministic, image-only scan simulation derived from the same invented pages. It adds grayscale, mild page skew, low contrast, light blur, seeded speckles, and JPEG artifacts; it is still not a physical scan or company document. Regenerate it with `uv run python scripts/processing/generate_commerce_scan_fixture.py`. Its visual transcription labels are in `commerce_degraded_scan_ground_truth.json`. This second fixture checks whether mild skew/noise breaks the OCR table path without changing source content or adding invented business evidence to RAG.

Run `uv run python scripts/processing/evaluate_scan_document_processing.py --output artifacts/evaluation/ocr/pipeline/commerce-scan-parser-smoke.json` to exercise the same `DocumentProcessor` path used for PDF uploads. Its CER/WER compare the source text chunks only; generated structured-table serialization is excluded and table rows/numeric cells are scored separately. If a structured table chunk replaced its source text chunk, that page is marked unscored for CER/WER instead of reporting a misleading text error rate. The clean fixture currently recovers its prose and all 3 table rows / 9 numeric cells exactly; that result validates only this synthetic smoke fixture.

The degraded fixture was evaluated with Tesseract 5.5.3, page PSM 11 at 1.5× and table PSM 3 at 2.5×. The current upload-path run reports micro CER/WER 0.0, 3/3 exact anchor rows, and 9/9 exact numeric cells; it also recovers the visible table title and all four semantic headers from OCR word boxes ([artifact](../../../artifacts/evaluation/ocr/pipeline/commerce-degraded-scan-v2-20261005.json)). The evaluator now supports semantic first-column labels such as `Region`, rather than assuming the parser key is always `label`. A live Tester API upload produced two persisted page previews, three parser chunks and one structured table with those same headers and rows ([artifact](../../../artifacts/evaluation/ocr/pipeline/commerce-degraded-scan-upload-live-20261005.json)). Both previews returned HTTP 200 `image/png`. The run is isolated in OCR test tables, not indexed in RAG. Older 2026-10-04 run records are historical and their run IDs may no longer exist. This remains a small synthetic robustness check, not evidence of real-document accuracy.
