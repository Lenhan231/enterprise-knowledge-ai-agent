## Current data flow

- Synthetic Kaggle Round 1 transaction, inventory, promotion, and shipment records remain in the private PostgreSQL `commerce` schema. The importer does not rewrite source values.
- `/api/commerce/dashboard` returns read-only aggregates from those tables. The UI filters by available year and separates inventory allocation, promotion planning, and nationwide logistics.
- The dashboard endpoint uses curated read-only aggregates. Decision answers check requested reporting dimensions against the selected domain's allowlisted columns, then attempt a question-specific SELECT; SQLGlot rejects other schemas, tables, columns, unsafe functions, unbounded results, and multi-statement queries, and PostgreSQL executes accepted SQL in a read-only transaction with a timeout. One repair attempt is made for rejected SQL; if a provider fails or SQL is rejected, the answer may use a bounded domain snapshot. If a requested dimension is missing, the agent returns a cited schema gap without substituting unrelated snapshot aggregates. Accepted SQL is retained in evidence metadata for review. The selected domain bounds available tables, so novel wording does not create benchmark-specific production branches.
- The dashboard opens on the selected decision domain: its headline cards and trend chart summarize that domain, while sales/margin is kept in a collapsed dataset-context section. The year filter applies to cards, charts, and tables. Inventory category rows use that year's final snapshot; with all years selected they default to the latest available snapshot. Promotion cards compare tagged and untagged items descriptively (mixed orders may occur in both groups) and expose a separately labeled merchandise gross-profit/margin proxy using catalog COGS; logistics cards are delivery-weighted regional summaries. These are synthetic observations, not company KPIs or causal estimates.

## Guardrails and known gaps

- All Commerce rows are synthetic. Do not present them as a real company's results.
- The stored `days_of_supply` is implausibly high (median rose from 95.7 days in 2012 to 330 days in 2022, with much larger means), so it is excluded from the dashboard pending source validation.
- Promotion tagging is observational and has no randomized holdout. The dashboard does not call tag differences promotion uplift or causal impact. The merchandise gross-profit/margin proxy subtracts catalog COGS from transaction net item sales; it is not contribution margin or campaign ROI, and the COGS assumption must be validated.
- The logistics records have no carrier, warehouse origin, route capacity, promised SLA, or service type. Regional transit summaries do not establish a network-optimization recommendation.
- For Commerce answers, `[C#]` citations support SQL observations, `[S#]` citations support retrieved operating methods, and `[L#]` citations describe schema/data coverage constraints. Missing fields must cite `[L#]`; do not use a regional aggregate to invent a delivery-delay cause or operational threshold.
- Decision retrieval applies the selected domain and active-reference metadata filter in PostgreSQL before dense/BM25 ranking, then reranks those candidates for the requested method. This prevents unrelated domains and archived guidance from consuming the bounded candidate pool; platform operating rules still require the platform to be named.
- Supplier lead time, ordering cost, holding cost, demand forecasts, and service-level targets are also absent. The schema has no separate low-stock alert or seller-defined minimum-stock threshold; do not substitute stockout/overstock counts for low-stock status. Replenishment advice must call out these missing inputs.
- Walmart supplier standards apply to Walmart supplier relationships; Shopee and TikTok platform rules are eligible only when the question explicitly names that platform. Do not apply any of them as Commerce Demo policy. Generic operating examples must remain attributed and cannot establish the mock business's own policy.
- DoorDash Ads' treatment/control, holdout and ghost-ad material supports an attributed example of causal campaign measurement, not Commerce Demo policy or a transferred performance benchmark. Use it to explain how incremental sales may be measured; campaign cost and contribution margin evidence are still needed to assess profit impact. Amazon Ads campaign-reporting content covers reported metrics and is not, by itself, a causal-uplift method.
- Platform rules can change. Cite the source page/version and date; never hardcode changing discount, shipping, or eligibility thresholds as universal rules.
- No full scan-only operating policy from a real company has been verified. The active Sam's Club PDF and Shopee Uni inventory PDF are mixed/image-heavy. Three explicitly fictional Commerce Demo policies are now full scan-only PDFs and active RAG references; they validate OCR-backed policy retrieval but are not evidence about a real retailer. Rate-limit fallbacks identify synthetic-policy provenance without quoting OCR text verbatim, since OCR chunks may contain recognition errors. The separate watermarked table fixture remains isolated for OCR/upload-quality checks.
- A second real Shopee Seller Education Hub PDF, “Tỷ lệ đơn hàng không thành công là gì?”, was revalidated from its official CDN URL and hash-registered in the source manifest, but not indexed: its publication date is absent and it contains dated seller thresholds and old interface instructions. Current OCR Lab processing returned 22 page previews, 24 chunks and 2 structured tables; five sparse pages invoked Tesseract (`vie+eng`, PSM 11, 2.5×), while screenshot-derived text remained noisy. It is a historical, Shopee-only OCR example, not current Commerce policy or exact-threshold evidence. The temporary OCR run was deleted and all four table counts for that run ID were verified as zero.

## Decision answer contract

For a decision question, the agent should first answer the requested factual comparison from SQL (`[C#]`), then select a method or decision criterion from the retrieved passage (`[S#]`), and connect both to a bounded recommendation. The document must explain the recommendation, not appear as an unrelated citation appended to generic advice. If the source only describes measurement, recommend that measurement; do not infer a guaranteed outcome. State that these are external examples, not Commerce Demo policy. Conditions must be qualitative unless a trusted source supplies an approved threshold. If the SQL lacks prerequisites for a safe operational change, the recommendation should name the next diagnostic or data collection step rather than inventing an action threshold.

Uploaded Commerce references must retain their selected evidence class: `company_policy_reference` is reserved for a verified, company-issued policy; `company_practice_reference` is an attributed external example; and `platform_operating_rule` is limited to the named platform. Retrieval ranks an in-scope company policy ahead of external examples. A label alone does not prove issuer, approval, or current validity; verify those before treating a policy as binding. The synthetic OCR fixture remains isolated and is not indexed as a business policy.

The report path now uses question intent to decide whether to retrieve operating references: descriptive rankings/comparisons use SQL only and must not gain unsolicited recommendations, experiments, or next steps; recommendation questions retrieve domain-matched RAG references. A validation gate retries unsolicited advice and then falls back to the requested SQL facts. If no applicable reference is retrieved for a decision question, the prompt and fallback do not prescribe a named external method. Missing schema fields and policy targets must cite `[L#]`, while observations cite `[C#]` and source-backed methods cite `[S#]`.
