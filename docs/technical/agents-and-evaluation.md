# Commerce agents and evaluation

## Two question paths

- **Policy/document Q&A:** `AgentRouter` sends document-only questions to `KnowledgeAgent`. Commerce retrieval first filters active sources by role and resolved domain, then applies the same source-scope ranking used for report evidence before generating an answer from those exact ranked passages. A source-specific question prioritizes a matching publisher, so a synthetic Commerce Demo policy does not outrank a named external guide. Explicit policy questions additionally filter to `company_policy_reference`, so an inventory-policy question does not retrieve promotion or logistics policies. External operating examples remain attributed to their publisher and scope; unmentioned platform rules are excluded.
- If answer generation is rate-limited after retrieval succeeds, RAG returns up to three cited source excerpts and the UI labels them as source-only fallback; it does not present them as a synthesized answer.
- If Hugging Face returns HTTP 402 for depleted credits, the process skips that fallback provider for 60 seconds to avoid repeating a known-billing failure; Groq retries and the normal safe fallback behavior remain active. Restarting the local app clears this in-memory cooldown.
- If question-specific Commerce SQL generation is provider-limited, malformed (including truncated JSON), or rejected by SQL validation, ReportAgent uses its cited deterministic answer from the bounded snapshot rather than failing the request. Malformed or unsafe SQL receives one correction attempt; a second rejection falls back without executing the query. Missing dimensions and valid empty results retain separate handling.
- A provider's empty text response is typed as a retryable generation failure. The configured alternate provider may be tried; if no usable text is returned, ReportAgent uses the same cited deterministic fallback instead of returning HTTP 503.
- Commerce SQL preflight treats an absent dimension as a schema gap when the question asks to group or filter by it; naming that field as evidence needed before a decision does not suppress available measures. Inventory questions about repeated/recurring flags require `COUNT(DISTINCT snapshot_date) FILTER (WHERE flag) >= 2` grouped by product and reject a single-snapshot date filter; they do not default to the latest date. This reports repeated snapshots, not distinct incidents. If SQL is provider-limited, the deterministic answer states when the aggregate did not measure repeat flags per product.
- Answer validation checks positive claims about dimensions excluded from the selected domain's approved schema. If a draft says current data can confirm or estimate a missing dimension, ReportAgent retries with the schema limitation; if the claim remains, it uses the cited deterministic fallback. Historical fields are not accepted as an unvalidated proxy for a missing forecast or location dimension.
- **Unseen Commerce questions:** after dashboard and explicit policy routing, `AgentRouter` uses the shared intent classifier to distinguish document-only questions from SQL/report requests. General method questions stay on KnowledgeAgent; method questions that refer to current observations (such as snapshot flags) go to ReportAgent for SQL plus domain-filtered operating references, even if the intent model labels them document-only. The dedicated Decision Support form classifies an unselected domain against the domain schemas; if that provider is unavailable, a Unicode-preserving keyword fallback normalizes common English inflections and abstains on ties or no signal. The detected domain is reflected as auto-detected in the answer UI. Explicit Decision Support form submissions always stay on ReportAgent.
- Source-framed method questions such as “Theo tài liệu, cần làm gì/so sánh yếu tố nào…?” route to KnowledgeAgent before the broad decision detector. If the question applies that method to current observations, it remains on ReportAgent. The dedicated Commerce Decision Support form sets `commerce_decision_support=true` and takes precedence, so its question always uses ReportAgent to combine SQL with retrieved guidance.
- **Decision support:** Questions asking what changed, what ranks highest, or what action to take go to `ReportAgent`. It obtains a bounded, read-only SQL result from the selected Commerce domain and retrieves relevant operating references. The answer separates observations, policy/method, decision limits, and missing data. Undefined qualitative wording in a source (for example, “many”) is an inspection cue, not a threshold or gate. Policy PDFs are shared with Q&A; no duplicate corpus is maintained.
- When answer generation is unavailable, the SQL fallback preserves returned rows and can derive an explicitly requested inventory stockout-category ranking from the matching count column. It labels that ranking as an inspection cue and does not treat aggregate flags as authorization to transfer stock.
- When a selected synthetic policy is OCR-derived, answer validation rejects verbatim OCR text. If generation is unavailable or still quotes it after retry, the deterministic fallback cites the policy but does not quote or paraphrase its OCR; it tells the user to inspect the original PDF. This avoids presenting recognition errors as policy wording.
- **Dashboard:** `/api/commerce/dashboard` returns curated aggregates from the private `commerce` schema. It does not depend on hard-coded KPI values or the document metric-review tables. Data-quality notes are scoped to the selected domain so inventory, promotion, and logistics caveats do not leak across tabs.
- Explicit chart requests for a recognized Commerce domain route to `DashboardAgent` before decision-report synthesis. It uses the same curated SQL aggregates as the dashboard page, returns the chart series with a `[C#]` observation citation, and honors any year range named in the question. Inventory fill rate is graphed separately from stockout/overstock counts because the units differ.

Question-specific SQL is generated within a domain table/column allowlist, parsed and checked with SQLGlot, executed read-only with a timeout and row limit, and returned with the query and dataset-provenance citation. It cannot query arbitrary schemas or mutate data. Commerce source data and the three policy PDFs are synthetic demo material; external cookbooks/practices are references, not Commerce Demo policy. The active promotion corpus includes Shopify's attributed marketing-planning guide for goals, audience, budget, and outcome review; DoorDash remains the reference for causal lift measurement. The agent must not invent thresholds or infer missing warehouse, campaign-cost, carrier, route, forecast or SLA facts.

## Evaluation

The nine SQL-plus-RAG decision cases are in `data/evaluation/commerce_decision_benchmark.json`; they record gold observations, expected behavior, missing data and whether an operating reference is required. `question_specific_sql_expected: false` means a bounded, cited aggregate or schema-gap answer is sufficient; it does not forbid a useful, domain-matched diagnostic query. The twelve retrieval cases, including three method-only cases, are in `data/evaluation/commerce_retrieval_cases.json`.

With the local app configuration and an Admin demo login in `.env`, replay all nine through the authenticated API:

```bash
PYTHONPATH=src uv run python tools/agents/evaluate_commerce_decision_support.py
```

Run one case while debugging with `--case-id INV-01`, or choose an output file with `--output`. The evaluator checks HTTP success, citation integrity, domain SQL provenance, synthetic-dataset disclosure, document source locations, required operating-reference presence, numeric fact coverage, and whether cited structured SQL rows contain the expected dimension/value groups. The row check recognizes SQL aliases and verifies grouping; it does not prove that the final answer associates those rows correctly or that its qualitative reasoning or recommendation is sound. Review each answer against its case's `gold_observations` and `expected_behavior` before reporting semantic scores. Provider rate limits stop the replay and leave the remaining case IDs in the output artifact.

Run the relevant regression suites with:

```bash
PYTHONPATH=src uv run python -m unittest tests.test_agents tests.test_rag tests.test_app_request_models -q
PYTHONPATH=src uv run python -m unittest tests.test_commerce_decision_evaluation tests.test_commerce_knowledge_manifest -q
```

OCR/upload quality is evaluated separately in `data/evaluation/ocr/README.md`; synthetic scan fixtures are not business evidence and stay isolated from the RAG corpus. Model/retrieval evaluation commands and limitations are listed in `tools/README.md`.
