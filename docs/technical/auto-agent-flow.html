Knowledge + SQL · Auto

Luồng Auto hiện tại

Auto chọn một agent khi một nguồn là đủ, hoặc lập kế hoạch gồm nhiều task khi câu hỏi cần cả số liệu có cấu trúc lẫn bằng chứng từ tài liệu.

Từ câu hỏi đến câu trả lời

1

Nhận câu hỏi và quyền của người dùng

Chat API tạo request có danh tính đã xác thực, conversation ID và retrieval settings, rồi chuyển sang AgentRouter.

2

Chọn route hoặc lập kế hoạch

Jev thử chọn Knowledge hoặc SQL cho câu hỏi độc lập, độ tin cậy cao. Nếu câu hỏi cần phối hợp, là follow-up, hoặc Jev không chắc, planner phân rã thành task và khai báo phụ thuộc.

Knowledge · tài liệu

Truy xuất nội dung được phép xem

Tìm tài liệu liên quan, lấy đoạn bằng chứng và citations. Phù hợp để trả lời chính sách, hướng dẫn, tiêu chí hoặc cách diễn giải.

SQL · dữ liệu có cấu trúc

Tạo và chạy truy vấn chỉ đọc

Lấy số liệu từ schema đã cấu hình; kiểm tra quyền, an toàn truy vấn và các quy tắc metric. Kết quả chứa rows, trạng thái query và giới hạn nếu có.

3

Kiểm tra quyền, thực thi và theo dõi task

Mỗi task phải có quyền tương ứng. Task phụ thuộc chỉ chạy khi task trước cung cấp kết quả; task độc lập có thể chạy song song. Router giữ task trace, số lần thử và thời gian thực thi.

4

Kiểm tra kết quả; thử sửa kế hoạch nếu cần

Nếu task thất bại hoặc không có dữ liệu, planner có thể được gọi lại tối đa một lần trong ngân sách còn lại. Task đã hoàn tất được giữ lại; câu hỏi cần làm rõ không bị tự động lập lại.

5

Tổng hợp và trả lời

Response ghép findings từ SQL với evidence/citations từ Knowledge, nêu limitations và chọn trạng thái hoàn tất, một phần, thất bại hoặc cần làm rõ.

Ví dụ: nên nhập thêm, quảng bá hay ngừng bán sản phẩm nào?

SQL trả lời “đang xảy ra điều gì?”

Doanh thu, giá vốn/lợi nhuận nếu có định nghĩa phù hợp, tốc độ bán và các dấu hiệu tồn kho có sẵn.

Knowledge trả lời “nên cân nhắc ra sao?”

Nguyên tắc bổ sung hàng, xử lý hàng chậm luân chuyển, giới hạn dữ liệu và căn cứ trong tài liệu.

Khuyến nghị cuối cần phân biệt dữ kiện SQL với hướng dẫn trong tài liệu. Tương quan trong dữ liệu không tự chứng minh quan hệ nhân quả; metric chưa được chuẩn hóa cần được ghi rõ là chưa xác minh.

Các trạng thái cần phân biệt

Hoàn tất

Các task cần thiết chạy được và có bằng chứng dùng được.

Một phần / cần làm rõ

Thiếu một nguồn, thiếu dữ liệu, hoặc câu hỏi còn mơ hồ về phạm vi.

Bị từ chối vì bảo mật

Người dùng thiếu quyền hoặc SQL không vượt qua kiểm tra an toàn. Đây khác với metric chỉ mang nhãn unverified.

SQL không được xem là đúng nghiệp vụ chỉ vì chạy thành công. Nhãn unverified có nghĩa kết quả phản ánh phép tính của truy vấn, chưa phải metric được phê duyệt.

Các điểm vào code

  • API chat và tạo runtime: src/app/agents.py
  • Định tuyến, đồ thị plan → execute → inspect → revise → combine: decision_support/router.py
  • Phân rã câu hỏi thành task: decision_support/planning.py
  • Quyền, phụ thuộc và thực thi task: decision_support/execution.py
  • Tổng hợp findings, citations và limitations: decision_support/response.py
Trang này mô tả luồng Auto trong code hiện tại; kết quả thực tế còn phụ thuộc kế hoạch được tạo, dữ liệu có sẵn, quyền người dùng và ngân sách xử lý.
